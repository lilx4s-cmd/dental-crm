# Patient travel and financial operations — delivery checkpoint

This continues the existing Next.js/NestJS/Prisma CRM. It includes the recovered local checkpoint and preserves its treatment-document, notification, permissions and WhatsApp fixes. It does not create another CRM or change paid plans.

## Source implementation

- Travel records link one existing patient, deal and visit. Repeated attachments use unique attachment keys; return flights stay in the same visit. Existing conversation files can be attached from the inbox. PDF extraction runs separately and supplies suggestions; flight confirmation remains a staff action. Image OCR is not configured; images remain readable attachments for manual confirmation.
- Flight instants validate IANA timezones and explicit UTC offsets, including daylight-saving changes. Hotel dates and readiness states are validated. Monthly panels query 30 visits per page with assignment/supervisor restrictions and Istanbul month boundaries. Summary counts ignore the list-only status filter and exclude cancelled visits from confirmed totals.
- Calendar OAuth uses one-time state, permission revalidation, encrypted offline tokens and administrator calendar selection. Saving a booking queues durable database work. Stable event IDs, revision checks, persisted locks, retries and separate event identities after cancellation/reconfirmation avoid duplicates. Cancellation deletes operational events and retains CRM records. No guests or invitation emails are added. Transient token failures remain retryable; revoked tokens require reconnection.
- Catalog and confirmed cost snapshots are versioned, with database immutability guards and audited exceptions. Decimal line and FX calculations round HALF_UP to two decimals. Included hotel/transfers contribute internal cost without another patient charge. Missing amounts suppress profit. Case summaries show separate visits and full-case amounts grouped by currency.
- Administrators define compensation eligibility, basis, exclusions, attribution, tiers and cancellation/refund rules. Defaults can be applied to all active staff, then individual rules revised. Monthly salary has one staff/month key and remains a business expense. Commission entries track estimates, earning, approval, payment, reversals and signed adjustments. Paid entries are preserved; reviewed manual exceptions are not undone by background calculation. Shared allocations have an audited administrator review workflow. Payments can be explicitly assigned to a treatment visit.
- New patient receipts inherit the invoice currency and use decimal balance arithmetic. Existing mixed-currency receipts require explicit reconciliation; historical payments are not silently rewritten.
- Internal-finance views are protected. The dashboard separates quoted invoices, receipts, outstanding balances, case costs, business expenses and commission recognition/payment periods. Operating-profit figures are withheld when required data is incomplete or a report limit is reached. Record business expenses only when they are not already case cost lines.

## Exact deployment and configuration requirements

1. Deploy this source to the existing Render API and Vercel web project; apply pending migrations with `prisma migrate deploy`. The checked live API was still on the older revision. Do not describe this source checkpoint as a completed live rollout.
2. In Google Cloud, enable Calendar API and create a **Web application** OAuth client. Configure the consent screen and these scopes: `openid`, `email`, `https://www.googleapis.com/auth/calendar.events`, and `https://www.googleapis.com/auth/calendar.calendarlist.readonly`.
3. Set the API environment values `GOOGLE_CALENDAR_CLIENT_ID`, `GOOGLE_CALENDAR_CLIENT_SECRET`, `GOOGLE_CALENDAR_REDIRECT_URI`, and a dedicated stable `ENCRYPTION_KEY` of at least 32 characters. The production callback is `https://dental-crm-qaz2.onrender.com/api/operations-finance/google/callback`; the authorized redirect URI must match exactly. Configure `WEB_APP_URL=https://dental-crm-web-psi.vercel.app`. Keep credentials on the server.
4. A clinic administrator must connect the clinic's chosen main Google account from **Travel costs and compensation → Google Calendar** and select a writable calendar. No email account has been assumed or hardcoded. Google app verification depends on audience/scopes and exemption eligibility; the cloud project's status was not available to verify. An external OAuth app left in Testing has refresh-token limitations; review the production consent setup before relying on unattended sync.
5. Existing Supabase private storage needs the correct `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` and `SUPABASE_STORAGE_BUCKET`. Storage configuration and its actual live bucket/region/quota could not be verified here. PDF extraction uses the bundled child-process parser; image OCR remains optional and unconfigured.
6. In production, the API sweeps persistent jobs while running. For a host that sleeps, configure an external scheduler. The supplied GitHub workflow dispatches every five minutes when repository secrets `CRM_API_ORIGIN=https://dental-crm-qaz2.onrender.com` and `CRM_OPERATIONS_WORKER_SECRET` are present. Set the same secret, at least 32 characters, as `OPERATIONS_WORKER_SECRET` on the API. The endpoint is `POST /api/operations-jobs/run`, using `x-crm-worker-key`. Repository scheduling starts from the default branch and may be delayed; it is not a guaranteed real-time worker. The workflow sends no request when its secrets are absent.
7. Enter real selling prices, procedure/lab costs, hotel/room/night costs, route/provider transfer costs, other fees and effective dates. Provide agreed FX rates and dates for mixed-currency reports. No new real costs were invented.
8. Define salary amount/currency/month-start or month-end policy; fixed/percentage/tier commission; eligibility trigger; revenue or profit basis; exclusions; attribution; per-case/per-visit scope; refund and cancellation policy. Package/category exclusions or collected-revenue exclusions without an explicit monetary allocation remain uncalculated instead of guessing. Shared amounts require administrator review. Existing unallocated payments are not guessed into a treatment visit.
9. Complete a controlled live OAuth/calendar lifecycle test after configuration: create, edit, cancel, reconfirm, retry and reconnect. Verify private upload access and phone layouts. Do not use real bookings or add guests for verification.
